# AxAIHub 插件格式规范 (NS 语言 + .axex / .axext)

> 本文档定义 AxAIHub 插件体系的两种文件格式与配套元数据语言，**供第三方开发者与开源分发使用**。
> 配套资源：打包工具 `axbuild` (CLI，见 `../tools/axbuild/`)、手机端 AxExt 打包工具、教程 `02-打包教程.md`。

## 1. 两种插件格式

| 格式 | 后缀 | 内容 | 适用场景 |
|------|------|------|----------|
| **.axext** | `.axext` | 明文 ZIP（可直接解压看源码） | 开源、学习、个人项目 |
| **.axex** | `.axex` | AES-256-GCM 加密 ZIP + 可选 Ed25519 作者签名 | 商业分发、闭源、防源码泄露 |

两种格式在 APP 内使用体验一致：导入后自动识别、解压到 `plugins/<plugin_id>/`，从目录中读取 `.ns` 元数据。

## 2. NS (NexusScript) 元数据语言

每个插件目录**必须**包含一个 `.ns` 文件（文件名为 `<任意>.ns`，如 `plugin.ns`、`com.example.demo.ns`）。APP 优先读取 `.ns`，回退 `manifest.json`（仅兼容旧包）。

### 2.1 语法规则

- **键值空格分隔**：`key value`，无需冒号、无需逗号。
- **嵌套对象**：`key {` 开始，独立一行的 `}` 结束。
- **数组**：`[ ... ]`，元素空格分隔。
- **字符串**：统一用双引号包裹（含路径、URL、中文等）。
- **注释**：`#` 开头到行尾；`#` 仅在非字符串内容中生效（字符串 `"..."` 内的 `#` 不触发注释）。
- **布尔 / 空**：`true` / `false` / `null`（不加引号）。
- 解析器**额外宽容**：即使键被写成 `"key"`（带引号），也会被当作普通键名处理（防止教程误写冒号语法导致解析失败）。

### 2.2 合法示例

```ns
# 插件清单 (NS 语言)
id "com.example.demo"
name "示例插件"
version "1.0.0"
author "开发者名"
description "演示 NS 语法"
type "local"
entry "index.html"

license {
  type "MIT"
  github "https://github.com/user/repo"
}

permissions {
  storage { quota "10MB" }
  network { domains ["api.example.com"] rateLimit 10 }
  clipboard { }
}
```

### 2.3 非法 / 不支持写法（请勿使用）

```ns
# 错误 1: 冒号语法 (NS 不用冒号)
id: "com.example.demo"

# 错误 2: 逗号分隔
name "示例插件",

# 错误 3: 字符串不加引号 (除 true/false/null 外一律加引号)
author 开发者名
```

> 说明：冒号写法虽被解析器"宽容"处理（把 `"id"` 当键），但 `id: "x"` 这类**值带冒号**的写法会产生非预期字段，规范上**不允许**。

## 3. .axex 二进制格式 (字节精确)

### 3.1 文件头（v1 与 v2 共有）

| 字段 | 长度 | 说明 |
|------|------|------|
| 魔数 | 4 字节 | 固定 ASCII `AXEX` |
| 版本号 | 1 字节 | `1` = 无签名；`2` = 含 Ed25519 签名 |
| 插件 ID 长度 | 1 字节 | `plugin_id` 的 UTF-8 字节数 |
| 插件 ID | 变长 | UTF-8，仅允许 `[a-zA-Z0-9_.-]` |
| Nonce | 12 字节 | AES-GCM 随机初始化向量 |

### 3.2 v2 在"插件 ID"与"Nonce"之间插入签名段

| 字段 | 长度 | 说明 |
|------|------|------|
| 公钥长度 | 2 字节 | 小端 `u16` |
| 公钥 | 变长 | 32 字节 Ed25519 公钥 |
| 签名长度 | 2 字节 | 小端 `u16` |
| 签名 | 变长 | 64 字节 Ed25519 签名 |

### 3.3 尾部

| 字段 | 长度 | 说明 |
|------|------|------|
| 密文 | 变长 | AES-256-GCM 加密后的 ZIP，含 16 字节 GCM 认证标签 |

**完整布局（v2）：**

```
AXEX [1] ver=2 [1] id_len [1] id[id_len]
     [2 LE] pubkey_len [32] pubkey
     [2 LE] sig_len   [64] sig
     [12] nonce [..] ciphertext(+tag)
```

**完整布局（v1）：**

```
AXEX [1] ver=1 [1] id_len [1] id[id_len]
     [12] nonce [..] ciphertext(+tag)
```

## 4. 密钥派生 (AES 加密层)

```
derived_key = PBKDF2-HMAC-SHA256(
    password = master_key,      // 见 4.1
    salt     = plugin_id,        // 插件 ID 字节
    iterations = 100_000,
    length   = 32                // 256 bit
)
```

- 加密算法：**AES-256-GCM**（AEAD，自带完整性认证）。
- Nonce 每次打包随机生成（12 字节）。

### 4.1 加密主密钥

- **默认密钥**：`AxAIHub-Default-Dev-Key!`（开发阶段内置，APP 与 CLI 一致）。
- **自定义密钥**：通过 `AXBUILD_MASTER_KEY` 环境变量或 `--master-key` 指定。
- 导入带**自定义**加密密钥的 `.axex` 时，用户需在 APP 导入界面填写**相同密钥**才能解密；使用默认密钥的包对用户透明（无需输入）。
- 密钥长度要求 ≥ 8 字节。

## 5. 作者签名 (Ed25519，可选，仅 v2)

签名用于**证明作者身份 + 防篡改**，与加密是两条独立链路：

- **没有默认签名密钥**：每位开发者必须用自己的 Ed25519 私钥（由 `axbuild keypair` 生成）。
- **签名对象**：对**明文 ZIP 字节**做 Ed25519 签名（`sk.sign(zip_bytes)`）。
- **公钥指纹**：`SHA-256(public_key)` 的前 8 字节，十六进制字符串。
- **APP 校验**（对标 APK 签名方案）：
  - **导入必验签**：解密后若包为 v2，用包内嵌公钥验证签名；验签失败（包体被篡改）拒绝加载。
  - **同签名更新**：已安装插件若带签名，更新包必须由**同一把私钥**签名（指纹一致），否则拒绝覆盖——对标 APK"更新必须同签名"规则；签名包也不允许被未签名包覆盖。
  - **指纹存储**：导入成功后签名指纹写入插件配置，供权限管理与更新校验使用。
- **可信开发者密钥库**（对标 APK"证书信任管理"）：APP 侧维护 `trusted_keys.json`（指纹 → 作者名/信任状态）。用户在插件管理中对某开发者"信任 / 取消信任"，签名信息（指纹、是否已信任）在插件详情中展示。
- **身份信任边界**：签名本身是"自签篡改检测"（包内嵌公钥）；**可信密钥库是用户侧的信任判断**，供用户决定"这个作者可不可信"。

## 6. 打包流程 (CLI `axbuild`)

```bash
# 生成自己的作者密钥对（首次）
axbuild keypair
# -> 输出 私钥(base64, 保密) / 公钥(base64, 公开) / 指纹

# 生成模板
axbuild new ./my-plugin --id com.example.demo --name "Demo" --author "me"

# 开源包
axbuild pack ./my-plugin my-plugin.axext

# 加密包（默认密钥）
axbuild pack ./my-plugin my-plugin.axex --encrypt

# 加密 + 作者签名（生产推荐）
axbuild pack ./my-plugin my-plugin.axex --encrypt --private-key "<私钥base64>"

# 查看包信息（含签名验证）
axbuild info my-plugin.axex
```

APP 端（手机内 AxExt 打包工具）产出与 CLI **字节级对齐**，两套工具生成的 `.axex` 可互相导入。

## 7. 插件可调用能力清单

插件**默认运行在独立插件窗口**（微信小程序式：Tauri 第二 WebView，与主窗口并行，可同时使用）：**插件页面本身就是窗口的顶层内容**（没有宿主页面、没有 iframe 可突破），通信由 Rust 注入窗口顶层的桥（`bridge_shim.js`）完成——插件侧可选用参考 SDK `samples/axplugin-sdk.js` 的 `AX.call` 封装 → 桥 → Tauri 后端。**独立窗口启动失败时自动降级**到同窗口宿主页面 AxPlugin.html（主窗口内，插件本体以无 `allow-same-origin` 的 iframe 承载，桥为 AxPlugin.html 内的 postMessage 分发）。**AI 反向调用插件函数**时，宿主以隐藏的静默模式加载 AxPlugin.html 与插件通信。**敏感命令（读任意文件 / 取明文密钥 / 聊天记录 / 本地记忆 / 终端 / Python / API 配置管理等）在 Rust 层校验「仅主窗口可用」**——插件即使拿到宿主全局对象，也无法触达这些命令。

**权限分两层（重要）**：

- **第 1 层：插件能力授权**（插件 `.ns` 声明 + **运行时申请制**）。APP 有某个能力 ≠ 插件有权限。插件必须调用 `permission.request({permission:'xxx'})` 申请 → 宿主弹确认框 → 授权写入后才可用；也可由用户在插件管理中手动开启。**未配置 = 未授权**，调用会被拒绝并返回"未授权，请先申请"。
- **第 2 层：系统权限通道**（`permission.check` / `permission.request`）。这是 APP 自身的系统权限（相机/麦克风/位置/通知/联系人/日历/短信/身体传感器/蓝牙/附近WiFi 等），插件通过 APP **借用**——不是插件权限，只是能力动作的前置条件。申请结果通过 `permission_result` 事件异步反馈（**未要到也有反馈**），插件据此提示用户。
- **APP 级专属（不开放给插件）**：电池优化豁免、无障碍服务——它们服务 APP 自身功能（保活、悬浮球识屏），插件声明无效。

### 7.1 已接通（当前版本可用）

| action | 说明 | 所需权限(第1层) |
|--------|------|----------|
| `app.info` | 获取应用信息 | 无 |
| `app.openUrl` | 在系统浏览器打开链接（仅 http/https） | 无 |
| `app.share` | 系统分享面板分享图片 | media |
| `storage.read` / `storage.write` | 读写插件私有数据文件 | storage |
| `storage.list` / `storage.delete` | 列举 / 删除插件数据文件 | storage |
| `network.fetch` | 经 APP 代理发起网络请求（域名白名单+限频） | network |
| `clipboard.read` / `clipboard.write` | 读写剪贴板 | clipboard |
| `device.vibrate` | 触发设备震动（`{duration?}` 毫秒，上限 5000） | vibration |
| `tts.speak` | 系统朗读文本（`{text, rate?, pitch?}`） | tts |
| `media.save` | 保存图片到系统相册（`{dataUrl, mediaType?}`） | media |
| `notify.show` | 发送系统通知（`{title, body}`，需 APP 已获通知权限） | notify |
| `ai.chat` | 调用宿主 AI 对话（`{messages, profileName?}`，支持多模态传图；方案由用户指定，插件无法绕过） | ai |
| `api.catalog` | 查看 APP 的 API 方案目录（脱敏：名称/模型/能力，**绝不返回密钥**） | 无 |
| `speech.recognize` / `speech.stop` | 系统语音识别（结果经 `speech_result` 事件异步回传 `{text, error}`） | speech |
| `file.pickFolder` | 系统文件夹选择器（SAF，阻塞轮询，返回 `{uri, name}`） | file |
| `camera.capture` | 拍照（调系统相机，结果经 `camera_result` 事件异步回传 `{success, mime, data(图片base64) \| error}`） | camera（系统权限） |
| `mic.record` | 录音（`{durationMs}` 秒，1-30 默认 10，结果经 `mic_result` 事件异步回传 `{success, mime, data(aac base64) \| error}`） | microphone（系统权限） |
| `geo.get` | 获取最近定位（同步返回 `{lat, lng, accuracy, provider}`；无定位返回 `null`） | location（系统权限） |
| `user.profile` | 读取宿主用户头像/昵称（返回 `{granted, name, avatar}`，未授权时浮层弹授权框） | profile |
| `permission.request` | 申请：能力权限弹宿主确认框；系统权限走 APP 通道 | 见上 |
| `permission.check` | 查询：能力授权状态 / APP 系统权限状态 | 见上 |
| `event.subscribe` / `event.unsubscribe` | 订阅 / 取消事件 | 无 |
| `lifecycle` 事件 | 安装/启用/禁用/卸载时自动派发（**无需订阅**） | 无 |
| `permission_result` 事件 | 系统权限申请结果异步回传（`{permType, granted, requestCode}`） | 无 |
| `camera_result` 事件 | 拍照结果异步回传（`{success, mime, data \| error}`，需先授权系统相机权限） | 无 |
| `mic_result` 事件 | 录音结果异步回传（`{success, mime, data \| error}`，需先授权系统麦克风权限） | 无 |

> 系统权限申请统一走 APP 通道，**结果必反馈**：弹窗授权成功/失败经 `permission_result` 事件送达插件；能力权限申请则同步返回 `{granted, perm}`。申请被拒或需要去系统设置时，插件都能感知并引导用户。

### 7.2 事件订阅

| 事件 | 说明 |
|------|------|
| `lifecycle` | 安装/启用/禁用/卸载时自动派发（无需订阅） |
| `permission_result` | 系统权限申请结果异步回传（`{permType, granted, requestCode}`） |
| `camera_result` / `mic_result` / `speech_result` | 拍照 / 录音 / 语音识别结果异步回传（`{success, mime, data \| error}` / `{text, error}`） |

> 事件经 `event.subscribe` / `event.unsubscribe` 订阅（`lifecycle` 无需订阅，自动派发）。相机/麦克风/定位**能力动作**（`camera.capture` / `mic.record` / `geo.get`）已接通（见 7.1），使用时需先经 `permission.request` 获取对应**系统权限**（弹系统授权窗），未授权时动作返回 `{granted:false, status:'need_permission', perm:'camera'|'microphone'|'location'}`。电池优化豁免、无障碍为 **APP 级专属**，插件声明无效。

### 7.3 AI 调用配额与密钥安全（护住用户钱包）

- **方案由用户指定（插件不能乱用）**：用户在「插件设置（插件运行页右上角 → 权限设置）或插件管理」里为每个插件**明确指定 AI 方案**（或"跟随全局默认"）。`ai.chat` 的方案解析优先级：**用户指定的 > 插件传入的 > 全局激活方案**——插件无法绕过用户指定，防止插件擅自切换方案扫描乱用。
- **配额（用户可配置，后端强制）**：插件调 `ai.chat` 受限制——每分钟 / 每日 / 每月调用上限 + 每月 token 预算。默认 10/分、100/天、1000/月、100 万 token/月；设为 `0` 表示不限制。超限调用返回错误（如"已达每日上限…"）。
- **配置与用量**：用户在「插件管理 → AI 权限」里调整配额，并实时查看用量（本分钟 / 今日 / 本月 / 月 token）。
- **真实计费**：调用成功后按模型响应 `usage.total_tokens` 累计到本月 token 桶，下轮调用前预检。
- **密钥永不入插件**：API 密钥以 AES 加密存于 APP（`profiles.enc`）；插件只能通过 `api.catalog` 看到**脱敏目录**（名称/模型/能力/模式），拿不到密钥、拿不到端点。`ai.chat` 由 APP 代理发起请求，密钥不出 APP。
- **多模态传图**：`ai.chat` 的 `messages` 支持 OpenAI 风格 content 数组（`text` + `image_url`），APP 自动转换为 Anthropic / Gemini 协议；图片走 base64 data URL。

## 8. 安全模型小结

1. **源码保护**：`.axex` 用 AES-256-GCM 加密，离线无法直读；解密密钥由 `master_key + plugin_id` 派生。
2. **作者身份 / 防篡改**：v2 包内嵌 Ed25519 签名，导入时强制验签，篡改即拒载；Release 构建拒绝未签名 v1 包。
3. **环境自检**：`.axex` 导入时检测模拟器 / 调试模式 / Root，命中则拒绝加载（"自毁"保护）。
4. **双重隔离**：默认独立窗口模式下插件页面为窗口顶层内容（无 iframe 可突破），桥（`bridge_shim.js`）由 Rust 注入窗口顶层；降级同窗口模式下插件本体进无 `allow-same-origin` 的 iframe，只能通过 postMessage 桥访问宿主能力。**敏感命令（读任意文件 / 取明文密钥 / 终端 / Python / 项目文件）在 Rust 层校验「仅主窗口可用」，插件一律拒绝**——无论哪种模式，插件都够不到密钥与设备级执行。
5. **权限最小**：未声明的权限（storage/network/clipboard/tts/media/ai 等）调用会被桥拒绝。

### 8.1 已知残余风险（如实披露）

以下为当前版本**已知、未根治**的风险面，均已做缓解但未彻底关闭，第三方开发者与安全研究者应知悉：

| 风险 | 现状与缓解 | 残余面 |
|------|-----------|--------|
| 插件身份可由命令参数传入（跨插件数据越权面） | 桥层强制使用宿主侧插件 ID，插件无法在消息中伪造；独立窗口模式下 Rust 以窗口关联的插件 ID 覆盖参数 | 主窗口（label=main）模式若宿主页面自身被注入，理论上可伪造参数（宿主代码视为可信） |
| 独立窗口启动失败时的 iframe 降级路径 | 降级模式下插件本体进无同源 iframe（跨源隔离，拿不到全局对象），通信只走 postMessage 桥 | 该路径的隔离强度依赖网页视图对跨源 iframe 的沙箱行为（多年稳定，但非独立进程级隔离） |
| 默认主密钥硬编码 | Release 构建拒绝**未签名 v1** `.axex`；v2 带作者签名 | 使用默认开发密钥打包的 v2 包仍可导入（密钥本身不保密，仅作混淆）；`.axext` 明文首装未签名包放行（安装界面有来源提示） |
| 环境自检可绕过 | 导入时检测模拟器 / 调试 / Root 并拒绝 | 自检仅 Android 生效且非硬件级，可被高级手段绕过（防御性措施，非安全边界） |
| 独立窗口为单例 | 同一时刻仅一个插件窗口 | 插件窗口之间互不可见，无跨插件 UI 面 |

> 上述风险不影响「插件够不到密钥与设备级执行」的核心边界（敏感命令在 Rust 层仅主窗口可用）。若你对某个风险面有更高要求，可联系维护者说明场景。

## 9. 版本与兼容性

- `.axex` 版本号 `1`（无签名）与 `2`（有签名）均被支持；新打包推荐 v2（带签名）。
- `.ns` 语法向上兼容；旧 `manifest.json` 包仍可导入（读取回退）。
- 加密默认密钥相同，自定义密钥只需保证打包端与导入端一致。
