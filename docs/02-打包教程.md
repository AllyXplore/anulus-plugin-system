## 1. 插件格式概述

Anulus 支持两种插件格式：

| 格式 | 后缀 | 安全性 | 适用场景 |
|------|------|--------|----------|
| **.axext** | `.axext` | 明文 ZIP，可解压查看源码 | 开源社区、个人项目、学习交流 |
| **.axex** | `.axex` | AES-256-GCM 加密，保护源码 | 商业分发、闭源插件 |

**两种格式的插件在 APP 内使用体验完全一致**，用户导入后自动识别并安装。加密插件导入时 APP 会自动解密，对用户透明。

## 2. 开发环境准备

### 2.1 方式一：手机端（推荐快速开发）

在 APP 内直接使用 **AxExt 打包工具**：
1. 打开 APP → 插件管理 → AxExt 打包工具
2. 在"生成插件模板"区域填写信息，生成模板
3. 用手机文件管理器编辑生成的 `index.html` 和 `plugin.ns`
4. 回到打包工具，打包为 `.axext` 或 `.axex`

### 2.2 方式二：电脑端 CLI（推荐生产环境）

安装 `axbuild` 命令行工具（源码位于本仓库 `tools/axbuild/`）：

```bash
# 从源码编译（需要 Rust 工具链: https://rustup.rs）
git clone <本仓库地址> axaihub-plugin-system
cd axaihub-plugin-system/tools/axbuild
cargo build --release

# 编译产物在 target/release/axbuild (或 axbuild.exe)
# 建议添加到 PATH 环境变量
```

或直接下载预编译的二进制文件（发布后见仓库 Releases 页）。

## 3. 创建插件项目

### 3.1 使用手机端打包工具生成模板

1. 打开 APP → 插件管理 → AxExt 打包工具
2. 填写：
   - **插件 ID**：`com.example.myplugin`（反向域名格式，全局唯一）
   - **插件名称**：`我的插件`（显示在插件列表中的名称）
   - **作者**：`作者名`
   - **目标目录**：选择或输入生成的目录路径
3. 点击"生成模板"，会在目标目录生成 `plugin.ns` 和 `index.html`

### 3.2 使用 CLI 生成模板

```bash
axbuild new ./my-plugin \
  --id com.example.myplugin \
  --name "我的插件" \
  --author "作者名"
```

生成的文件结构：

```
my-plugin/
├── plugin.ns        # 插件清单（必需，NS 语言）
└── index.html       # 插件入口页面（必需，可引用其他资源）
```

### 3.3 plugin.ns 模板（NS 语言）

NS 是 Anulus 自定义的插件元数据类型语言，使用**空格分隔的键值**语法（不是 JSON，也不需要冒号）。字符串用双引号包裹，嵌套对象用 `key {` 开始、`}` 结束，数组用 `[ ... ]` 包裹。

```ns
# 插件清单（NS 语言，空格分隔键值）
id "com.example.myplugin"
name "我的插件"
version "1.0.0"
author "作者名"
description "插件功能描述"
type "local"
entry "index.html"

license {
  type "MIT"
  github "https://github.com/user/repo"
}

# 权限声明见 3.4
permissions {
  storage { quota "10MB" }
  network { domains ["api.example.com"] rateLimit 10 }
  clipboard { }
}
```

**字段说明：**

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 插件唯一标识，仅允许小写字母、数字、连字符、下划线 |
| `name` | string | 是 | 插件显示名称 |
| `version` | string | 是 | 语义化版本号，如 `1.0.0` |
| `author` | string | 是 | 作者名称 |
| `description` | string | 否 | 插件功能描述 |
| `type` | string | 是 | `local`（本地）或 `remote`（网页） |
| `entry` | string | 是 | 入口文件，local 类型默认 `index.html` |
| `license` | object | 否 | 许可证信息 |
| `permissions` | object | 否 | 权限声明（见下文） |

### 3.4 权限声明

在 `plugin.ns` 中通过 `permissions { ... }` 块声明（NS 空格语法，注意是复数）：

```ns
permissions {
  storage { quota "10MB" }              # 本地存储（已接通）
  network {                             # 网络请求（已接通）
    domains ["api.example.com"]         # 域名白名单
    rateLimit 10                        # 每分钟请求上限
  }
  clipboard { }                         # 剪贴板读写（已接通）
  vibration { }                         # 设备震动 device.vibrate（已接通）
  tts { }                               # 系统朗读 tts.speak（已接通）
  media { }                             # 保存/分享图片 media.save、app.share（已接通）
  notify { }                            # 发送系统通知 notify.show（已接通）
  ai { }                                # 可被 AI 调用（ai.chat 与 AI 反向调用插件函数，已接通）
}
```

> **权限是运行时申请制**：APP 有某个能力 ≠ 插件有权限。插件声明权限后，运行时调用 `permission.request({permission: 'network'})` → 宿主弹确认框 → 授权后才可用；用户也可在插件管理中手动开关。**未配置 = 未授权**，直接调用能力会被拒绝并提示"请先申请"。
>
> **系统权限是另一层（借用 APP 通道）**：相机/麦克风/位置/通知/联系人/日历/短信/身体传感器/蓝牙/附近WiFi 等系统权限由 APP 持有，插件通过 `permission.check` / `permission.request` **借用**，不作为插件权限声明。申请结果通过 `permission_result` 事件异步反馈（**没要到也有反馈**）。**电池优化豁免、无障碍是 APP 级专属功能，与插件无关，插件声明无效**，请不要在插件里声明。

## 4. 编写插件代码

### 4.1 基本 HTML 结构

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">
  <title>我的插件</title>
  <style>
    body { font-family: -apple-system, sans-serif; padding: 16px; }
    button { padding: 8px 14px; margin: 4px; }
  </style>
</head>
<body>
  <h2>我的插件</h2>
  <button onclick="getAppInfo()">获取应用信息</button>
  <div id="log"></div>

  <script>
    // 与宿主通信的封装
    let reqSeq = 0;
    const pending = {};

    function callHost(action, args, timeout = 5000) {
      const id = 'req-' + (++reqSeq);
      return new Promise((resolve, reject) => {
        const timer = setTimeout(() => {
          delete pending[id];
          reject(new Error('请求超时'));
        }, timeout);
        pending[id] = { resolve, reject, timer };
        window.parent.postMessage({
          source: 'axplugin',
          id: id,
          action: action,
          args: args || {}
        }, '*');
      });
    }

    window.addEventListener('message', function(e) {
      if (e.data.source !== 'axhost') return;
      const handler = pending[e.data.id];
      if (!handler) return;
      clearTimeout(handler.timer);
      delete pending[e.data.id];
      if (e.data.error) handler.reject(e.data.error);
      else handler.resolve(e.data.result);
    });

    function log(msg) {
      document.getElementById('log').textContent += msg + '\n';
    }

    async function getAppInfo() {
      try {
        const info = await callHost('app.info', {});
        log('应用信息: ' + JSON.stringify(info));
      } catch (err) {
        log('获取失败: ' + err);
      }
    }
  </script>
</body>
</html>
```

### 4.2 通信协议

插件通过 `window.parent.postMessage` 与 APP 宿主通信：

**请求格式：**
```javascript
window.parent.postMessage({
  source: 'axplugin',    // 固定标识
  id: 'req-001',         // 唯一请求 ID
  action: 'storage.read', // 要调用的能力名称
  args: { filename: 'data.json' }  // 参数
}, '*');
```

**响应格式：**
```javascript
{
  source: 'axhost',      // 固定标识
  id: 'req-001',         // 对应请求的 ID
  result: { ... },       // 成功时的结果
  error: { ... }         // 失败时的错误信息
}
```

### 4.3 可用 API 列表

> 状态栏：`已接通` = 当前版本可用。

| action | 说明 | 参数 | 所需权限 | 状态 |
|--------|------|------|----------|------|
| `app.info` | 获取应用信息 | `{}` | 无需权限 | 已接通 |
| `app.openUrl` | 在系统浏览器打开链接 | `{url}`(仅http/https) | 无需权限 | 已接通 |
| `app.share` | 系统分享面板分享图片 | `{dataUrl, mediaType?}` | media | 已接通 |
| `storage.read` | 读取插件数据文件 | `{filename}` | storage | 已接通 |
| `storage.write` | 写入插件数据文件 | `{filename, dataB64}` | storage | 已接通 |
| `storage.list` | 列出插件数据目录 | `{}` | storage | 已接通 |
| `storage.delete` | 删除插件数据文件 | `{filename}` | storage | 已接通 |
| `network.fetch` | 发起网络请求 | `{url, method?, headers?, bodyB64?}` | network | 已接通 |
| `clipboard.read` | 读取剪贴板 | `{}` | clipboard | 已接通 |
| `clipboard.write` | 写入剪贴板 | `{text}` | clipboard | 已接通 |
| `device.vibrate` | 触发设备震动 | `{duration?}` 毫秒(上限5000) | vibration | 已接通 |
| `tts.speak` | 系统朗读文本 | `{text, rate?, pitch?}` | tts | 已接通 |
| `media.save` | 保存图片到系统相册 | `{dataUrl, mediaType?}` | media | 已接通 |
| `notify.show` | 发送系统通知 | `{title, body}` | notify | 已接通 |
| `ai.chat` | 调用宿主 AI 对话（支持多模态传图，方案由用户指定） | `{messages, profileName?}` | ai | 已接通 |
| `api.catalog` | 查看 API 方案目录（脱敏，不含密钥） | `{}` | 无 | 已接通 |
| `speech.recognize` / `speech.stop` | 系统语音识别（结果走 speech_result 事件） | `{lang?}` | speech | 已接通 |
| `file.pickFolder` | 系统文件夹选择器 (SAF) | `{}` | file | 已接通 |
| `user.profile` | 读取宿主用户头像/昵称（未授权时浮层弹授权框） | `{}` | profile | 已接通 |
| `permission.request` | 申请权限（能力权限弹宿主确认框；系统权限走 APP 通道） | `{permission}` | 见上 | 已接通 |
| `permission.check` | 查询权限（能力授权状态 / APP 系统权限状态） | `{permission}` | 见上 | 已接通 |
| `camera.capture` | 拍照（调系统相机，结果走 camera_result 事件） | `{}` | camera（系统权限） | 已接通 |
| `mic.record` | 录音（结果走 mic_result 事件） | `{durationMs}` 秒(1-30) | microphone（系统权限） | 已接通 |
| `geo.get` | 获取最近定位（同步返回） | `{}` | location（系统权限） | 已接通 |
| `event.subscribe` | 订阅事件（如 lifecycle） | `{events: [...]}` | 无需权限 | 已接通 |
| `event.unsubscribe` | 取消事件订阅 | `{}` | 无需权限 | 已接通 |

> 说明：事件订阅支持的事件为 `lifecycle`（安装/启用/禁用/卸载时自动派发，无需订阅）、`permission_result`（系统权限申请结果）、`camera_result` / `mic_result` / `speech_result`（拍照/录音/语音识别结果），经 `event.subscribe` 订阅。
>
> 相机/麦克风/定位能力动作已接通：使用前需先 `permission.request({permission:'camera'|'microphone'|'location'})` 获取系统权限（弹系统授权窗），未授权时动作返回 `{granted:false, status:'need_permission', perm:...}`；授权后拍照/录音结果分别经 `camera_result` / `mic_result` 事件异步回传，`geo.get` 同步返回 `{lat,lng,accuracy,provider}`。

### 4.4 AI 调用与传图示例（需先申请 `ai` 权限）

```javascript
// 1) 查看 APP 的 API 方案目录 (脱敏, 拿不到密钥)
const catalog = await callHost('api.catalog', {});
// catalog.profiles: [{name, model, abilities, chatMode, keyPresent}, ...]

// 2) 文本对话 (缺省用当前激活方案)
const r1 = await callHost('ai.chat', {
  messages: [{ role: 'user', content: '用一句话介绍自己' }]
});
console.log(r1.content);

// 3) 指定方案 + 多模态传图 (OpenAI 风格, 图片为 base64 data URL)
const r2 = await callHost('ai.chat', {
  profileName: '我的视觉方案',
  messages: [{
    role: 'user',
    content: [
      { type: 'text', text: '这张图里有什么?' },
      { type: 'image_url', image_url: { url: 'data:image/png;base64,....' } }
    ]
  }]
});
```

> **方案与配额**：`ai.chat` 用哪个方案由**用户在该插件设置里指定**（插件传入的 profileName 优先级低于用户指定，防止插件擅自换方案）。调用受每分钟/每日/每月上限与月 token 预算限制（默认 10/分、100/天、1000/月、100 万 token/月，0=不限制），超限返回错误；用量可在「插件设置 → 权限设置」实时查看。**API 密钥永远在 APP 内部，插件拿不到**。


## 6. 打包为 .axex（加密格式）

.axex 是加密格式，保护插件源码不被直接查看。加密使用 AES-256-GCM 算法，密钥由 APP 内置密钥 + 插件 ID 派生，**无需输入密码**。

### 6.1 使用手机端打包工具

1. 打开 APP → 插件管理 → AxExt 打包工具
2. 在"打包 .axex (加密)"区域：
   - **源目录**：选择包含 `plugin.ns` 和 `index.html` 的插件目录
   - **输出路径**：输入或选择输出文件路径（如 `/sdcard/my-plugin.axex`）
3. 点击"打包 .axex"，APP 自动完成加密打包

### 6.2 使用 CLI 打包

.axex 支持两层保护：**加密**（AES-256-GCM，保护源码）+ **签名**（Ed25519，证明作者身份、防篡改）。加密层使用默认密钥即可；签名层必须由开发者提供**自己的** Ed25519 私钥，没有默认签名密钥。

```bash
# 生成你自己的 Ed25519 密钥对（首次使用）
axbuild keypair
# 输出 private_key（base64，保密）/ public_key（base64，公开）/ fingerprint

# 仅加密（使用内置默认密钥，开发期够用）
axbuild pack ./my-plugin my-plugin.axex --encrypt

# 加密 + 用自己的私钥签名（生产环境推荐，可验证作者）
axbuild pack ./my-plugin my-plugin.axex --encrypt \
  --private-key "你的Ed25519私钥(base64)"

# 使用自定义加密密钥（可选，需与 APP 端导入时提供的密钥一致）
export AXBUILD_MASTER_KEY="your-32-byte-key-here!!!!!"
axbuild pack ./my-plugin my-plugin.axex --encrypt --private-key "私钥"
```

> 导入带自定义加密密钥的 .axex 时，用户需在 APP 导入界面填写相同密钥；签名则无需用户关心，APP 会用内置的开发者公钥库验证。

### 6.3 文件格式（v2，含签名段）

```
.axex v2 文件结构（字节精确）：
┌────────────────────────────────────────────┐
│ 魔数 "AXEX"        (4 字节)                  │
│ 版本号             (1 字节, 当前为 2)         │
│ 插件 ID 长度        (1 字节)                  │
│ 插件 ID            (UTF-8, 可变长度)          │
│ 公钥长度            (2 字节, 小端)            │
│ 公钥               (32 字节, Ed25519)         │
│ 签名长度            (2 字节, 小端)            │
│ 签名               (64 字节, Ed25519)         │
│ Nonce              (12 字节, 随机生成)        │
│ AES-256-GCM 密文    (含 16 字节认证标签)        │
└────────────────────────────────────────────┘
  v1（无签名段）：版本号=1，跳过"公钥长度~签名"四段。

加密密钥派生：
  derived_key = PBKDF2-SHA256(
    master_key,      // APP 内置默认密钥或自定义密钥
    plugin_id,       // 插件 ID 作为 salt
    100000,          // 迭代次数
    32               // 输出 32 字节 (256 位)
  )

签名（可选，v2 才有）：
  私钥 = Ed25519 私钥（开发者自备，无默认值）
  签名 = 私钥对"ZIP 原始字节"做 Ed25519 签名
  指纹 fingerprint = SHA-256(公钥) 前 8 字节的十六进制
  APP 用开发者公开的公钥验证签名，未通过则拒绝加载。
```

> 加密与签名是**两条独立链路**：加密保护源码不被查看，任何人都可用默认密钥打包；签名证明作者身份与完整性，必须由开发者用自己的私钥完成。两者可分别使用。

### 6.4 密钥说明

- **加密默认密钥**：`Anulus-Default-Dev-Key!`（开发阶段内置，无需配置）
- **自定义加密密钥**：生产环境建议通过 `AXBUILD_MASTER_KEY` 环境变量设置自定义密钥，避免所有人用同一把默认密钥
- **签名密钥**：Ed25519 签名**没有默认值**，每位开发者必须用自己的私钥（由 `axbuild keypair` 生成）。这正是"让用户自己签名、不用默认"的设计——签名身份完全由开发者掌控
- **密钥一致性**：加密层只要 APP 端导入时提供的密钥与打包时一致，即可解密；签名层由开发者公钥验证，与加密密钥无关
- **更新规则（对标 APK 同签名更新）**：已签名插件更新时，新包必须由**同一把私钥**签名（指纹一致），否则 APP 拒绝覆盖安装；签名包也不允许被未签名包覆盖
- **可信作者**：插件详情页展示签名指纹，可"信任/取消信任"某开发者；信任关系存于 APP 可信密钥库，供用户判断作者可信度

### 6.5 安全机制

.axex 插件在导入时会自动执行环境安全检查：

- 检测是否在模拟器上运行
- 检测是否处于调试模式
- 检测是否拥有 Root 权限

任何一项检测不通过，APP 将拒绝加载该插件，实现"自毁"保护。

`plugin.ns` 的 `license` 块可配置 `updateCheck` 字段，记录更新检查地址（元数据，用于标识更新来源）：

```ns
license {
  type "MIT"

}
```

`updateCheck` URL 返回标准的 `plugin.ns`，其 `version` 字段用于版本比较。

## 9. 常见问题

### Q: .axext 和 .axex 可以互相转换吗？

可以，通过打包工具即可：
- `.axext` → `.axex`：用打包工具从源目录重新打包为 `.axex`
- `.axex` → `.axext`：无法直接转换，因为 `.axex` 是加密的。解密后重新打包为 `.axext`

### Q: .axex 加密后文件会变大吗？

会有少量增加（约 50-100 字节），主要是加密元数据（nonce、认证标签、格式头）的开销。

### Q: 加密插件加载速度会变慢吗？

首次导入时需解密，增加约 50-200ms。后续加载速度与 `.axext` 一致。

### Q: 用户导入 .axex 需要输入密码吗？

使用**默认密钥**打包的 .axex 不需要——密钥由 APP 内置默认密钥 + 插件 ID 自动派生，对用户透明。若开发者用**自定义加密密钥**打包，导入时用户需在 APP 中填写相同密钥才能解密；签名验证则对用户透明（APP 用开发者公钥校验）。

### Q: 如何确保加密密钥的安全性？

- 开发阶段使用内置默认密钥即可
- 生产环境应通过环境变量 `AXBUILD_MASTER_KEY` 设置自定义密钥
- 自定义密钥需与 APP 端使用的密钥一致，否则无法解密
- 密钥保管是安全的核心，建议使用密钥管理服务

### Q: 插件支持 WASM 吗？

支持。插件目录中可包含 `.wasm` 文件，在 `index.html` 中通过 `fetch` + `WebAssembly.instantiateStreaming` 加载。

### Q: 插件可以访问网络吗？

需要声明 `network` 权限，并在 `domains` 白名单中列出允许访问的域名。网络请求由 APP 代理，插件无法直接发起请求。

## 10. 附录：API 参考

### 10.1 完整通信示例

```javascript
// 封装好的宿主调用函数
function callHost(action, args, timeout = 5000) {
  const id = 'req-' + Date.now() + '-' + Math.random().toString(36).slice(2);
  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => {
      delete pending[id];
      reject(new Error('请求超时'));
    }, timeout);
    pending[id] = { resolve, reject, timer };
    window.parent.postMessage({
      source: 'axplugin',
      id: id,
      action: action,
      args: args || {}
    }, '*');
  });
}

// 监听响应
const pending = {};
window.addEventListener('message', function(e) {
  if (e.data.source !== 'axhost') return;
  const handler = pending[e.data.id];
  if (!handler) return;
  clearTimeout(handler.timer);
  delete pending[e.data.id];
  if (e.data.error) handler.reject(e.data.error);
  else handler.resolve(e.data.result);
});
```

### 10.2 生命周期事件（已接通）

APP 在**安装 / 启用 / 禁用 / 卸载**时通过 postMessage 派发 `lifecycle` 事件。插件**无需订阅**即可接收，消息格式为 `{source:'axhost', type:'event', event:'lifecycle', payload:{type, timestamp}}`：

```javascript
window.addEventListener('message', function(e) {
  if (e.data.source !== 'axhost') return;
  // 生命周期事件
  if (e.data.type === 'event' && e.data.event === 'lifecycle') {
    const phase = e.data.payload.type; // install | enable | disable | uninstall
    console.log('生命周期阶段:', phase);
    if (phase === 'install') { /* 初始化 */ }
  }
  // 普通请求回包仍按 id 匹配（见 10.1）
});
```

> 注意：生命周期通过事件消息下发，**不是**在 `plugin.ns` 中声明回调函数的机制，旧文档的 `lifecycle { install "onInstall" }` 写法已废弃。

### 10.3 事件订阅

`lifecycle` 事件无需订阅即可接收（安装/启用/禁用/卸载时自动派发）。其他事件通过 `event.subscribe` 主动订阅（见 4.3）：

| 事件名 | 触发时机 |
|--------|----------|
| `lifecycle` | 安装/启用/禁用/卸载（无需订阅） |
| `permission_result` | 系统权限申请结果异步回传 |
| `camera_result` / `mic_result` / `speech_result` | 拍照 / 录音 / 语音识别结果异步回传 |
