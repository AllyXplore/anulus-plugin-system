# 2. 模块设计

## 2.1 NS 解析器 (parser.rs)

### 职责

- 词法分析：将 `.ns` 文件文本转换为 Token 流
- 语法分析：将 Token 流转换为 AST（抽象语法树）
- 语义校验：执行校验规则（必需字段、编号唯一性、类型合法性等）
- 输出：`NsManifest` 结构体

### 内部结构

```
Parser
 ├── Lexer: 字符流 → Token 流
 │    ├── Identifier, String, Number, Bool
 │    ├── NumberLiteral (#1, #2, ...)
 │    ├── BlockStart, BlockEnd
 │    ├── ListStart, ListEnd
 │    └── Newline, Eof
 ├── Parser: Token 流 → AST
 │    ├── parse_document() → Vec<Statement>
 │    ├── parse_kv() → (String, Value)
 │    ├── parse_block() → Block
 │    ├── parse_api() → ApiDecl
 │    └── parse_list() → Vec<Value>
 └── Validator: AST → NsManifest
      ├── check_required_fields()
      ├── check_api_number_uniqueness()
      ├── check_domain_wildcard()
      └── to_manifest() → NsManifest
```

### NsManifest 数据结构

```rust
struct NsManifest {
    // 基本信息
    id: String,                    // 插件唯一标识
    name: String,                  // 显示名
    version: String,               // 语义化版本号
    author: String,                // 作者
    description: Option<String>,   // 描述
    license: Option<String>,       // 开源协议
    icon: Option<String>,          // 图标路径
    min_app_version: Option<String>, // 最低 APP 版本
    update_url: Option<String>,    // 更新地址
    ns_version: u32,               // NS 语法版本

    // 类型
    plugin_type: PluginType,       // axext | axex | remote

    // 入口
    ui: Option<String>,            // UI 入口路径
    entry: Option<String>,         // WASM 入口路径
    url: Option<String>,           // 远程插件 URL

    // API 声明
    apis: Vec<ApiDecl>,            // 编号 → 内部 API 映射

    // AI 工具
    tools: Vec<ToolDecl>,          // 注册的 AI 工具

    // 依赖
    deps: Vec<DepDecl>,            // 依赖的插件

    // 生命周期钩子
    hooks: Vec<HookDecl>,          // 钩子脚本

    // 配置
    configs: Vec<ConfigDecl>,      // 配置项

    // 调试
    debug: Option<DebugConfig>,    // 调试配置
    dev: Option<DevConfig>,        // 开发配置
}

struct ApiDecl {
    number: u32,                   // #1, #2, ...
    api_name: String,              // 内部 API 名
    reason: Option<String>,        // 用途说明
    rate: Option<u32>,             // 频率限制
    domains: Option<Vec<String>>,  // 域名白名单
    system: bool,                  // 是否需要系统权限
}
```

## 2.2 插件管理器 (manage.rs)

### 职责

- 插件安装：解压、解析 NS、校验、注册、触发 install 钩子
- 插件卸载：触发 uninstall 钩子、删除文件、清除授权记录
- 插件启用/禁用：更新状态、触发 enable/disable 钩子
- 插件列表：查询已安装插件、过滤、排序
- 插件更新：检查更新、下载新版本、执行 update 钩子

### 安装流程

```
用户选择 .axext/.axex 文件
  → 解压到临时目录
  → 解析 plugin.ns → NsManifest
  → 校验:
      ├── NS 校验规则 (parser validator)
      ├── minAppVersion 检查
      ├── 依赖检查 (已安装? 版本满足?)
      └── 循环依赖检测
  → 通过 → 移动到插件安装目录
  → 创建授权记录 (所有 api #N 初始为未授权)
  → 执行 install 钩子脚本
  → 安装完成
```

### 文件结构

```
插件安装目录:
  plugins/
    └── com.example.plugin/          # 插件 ID 作为目录名
        ├── plugin.ns                # NS 清单文件
        ├── index.html               # UI 入口
        ├── icon.png                 # 图标
        ├── wasm/
        │   └── main.wasm            # WASM 核心逻辑
        ├── scripts/
        │   ├── init.js              # 安装钩子
        │   └── cleanup.js           # 卸载钩子
        └── data/                    # 插件私有数据目录
            ├── config.json          # 配置存储
            └── ...                  # 插件运行时数据
```

## 2.3 API 桥接层 (api.rs)

### 职责

- 维护 `#N → 内部 API` 映射表
- 执行权限检查（用户是否已授权）
- 执行频率限制（rate）
- 执行域名白名单检查（domains）
- 执行参数消毒（路径穿越检测）
- 执行调用超时
- 返回统一格式的响应

### 调用流程

```
AX.call(1, { url: "https://api.example.com/data" })
  → API 桥接层
  → 查找 #1 → "network.fetch"
  → 检查权限: 已授权? → 未授权 → 触发授权弹窗
  → 用户允许 → 记录授权
  → 检查频率: 60次/分钟? → 未超限
  → 检查域名: "api.example.com" 在白名单? → 是
  → 参数消毒: 无路径参数
  → 执行: HTTP GET https://api.example.com/data
  → 返回: { success: true, data: { ... } }
```

### 内部 API 路由表

```rust
struct ApiRouter {
    mappings: HashMap<u32, ApiRoute>,  // #N → 路由
}

struct ApiRoute {
    api_name: String,                  // 内部 API 名
    handler: fn(Params) -> Result,     // 处理函数
    permission_check: bool,            // 是否需要权限检查
    rate_limiter: Option<RateLimiter>, // 频率限制器
    timeout: Duration,                 // 超时时间
}
```

## 2.4 沙箱管理 (webview.rs)

### 职责

- 创建插件 UI 的 iframe 容器
- 注入 CSP 头
- 注入 `AX` 全局对象
- 管理 iframe 生命周期
- 静默插件无需 iframe

### CSP 策略

```
Content-Security-Policy:
  default-src 'self' 'unsafe-inline';
  script-src 'self' 'unsafe-inline' 'unsafe-eval';
  connect-src 'none';
  img-src 'self' data: blob:;
  frame-src 'none';
  form-action 'none';
```

### AX 对象注入

```javascript
// APP 注入到插件 iframe 的全局对象
window.AX = {
    call: function(number, params) {
        // 通过 postMessage 发送到 APP 宿主
        // APP 宿主处理并返回结果
        return new Promise((resolve, reject) => {
            const id = generateMessageId();
            pendingCalls[id] = { resolve, reject };
            iframe.contentWindow.postMessage({
                type: 'ax_api_call',
                id: id,
                number: number,
                params: params
            }, '*');
        });
    }
};
```

## 2.5 WASM 运行时 (wasm.rs)

### 职责

- 加载 WASM 模块到沙箱
- 提供 `AX` 导入函数
- 管理 WASM 实例生命周期
- 仅适用于 `.axex` 类型

### WASM 导入接口

```wasm
// WASM 模块从宿主导入的函数
(import "ax" "call" (func $ax_call (param i32 i32 i32) (result i32)))
// 参数: (number, params_ptr, params_len)
// 返回: result_ptr (指向 JSON 结果的内存地址)
```

# 4. 安全架构

## 4.1 多层防护

```
第一层: NS 文件校验
  ├── 必需字段存在性
  ├── id 格式 (反向域名)
  ├── 域名白名单禁止 *
  ├── 路径禁止 ..
  └── 内部 API 名合法性

第二层: 沙箱隔离
  ├── iframe 隔离 (不同域)
  ├── CSP 限制 (connect-src 'none')
  ├── WASM 沙箱 (无外部访问)
  ├── 插件间数据隔离 (独立目录)
  └── 存储配额限制

第三层: 权限控制
  ├── 声明-授权模型 (NS 声明, 用户授权)
  ├── 运行时弹窗确认
  ├── 频率限制 (rate)
  ├── 域名白名单 (domains)
  └── 参数消毒 (路径穿越检测)

第四层: 运行时防护
  ├── 调用超时
  ├── 钩子脚本权限限制
  ├── 远程插件 HTTPS 强制
  ├── dev 块打包时剥离
  └── 审计日志
```

## 4.2 安全边界矩阵

| 攻击面 | 防护措施 | 严重程度 |
|--------|---------|---------|
| 恶意 NS 文件 | 解析器校验 | 高 |
| 路径穿越 | 参数消毒 | 高 |
| XSS 攻击 | CSP + iframe 隔离 | 高 |
| 数据泄露 | 插件间数据隔离 | 高 |
| 存储耗尽 | 存储配额 | 中 |
| 网络滥用 | 域名白名单 + 频率限制 | 中 |
| 权限滥用 | 实时弹窗确认 | 高 |
| 远程代码执行 | WASM 沙箱 + CSP | 高 |
| 钩子脚本滥用 | 脚本权限限制 | 中 |
| 拒绝服务 | 调用超时 | 中 |

# 5. 打包格式规范

## 5.1 .axext 格式（开源插件）

```
容器格式: ZIP (无加密)
文件扩展名: .axext
MIME 类型: application/vnd.axaihub.plugin.axext

包结构:
  plugin.ns              # 必需: NS 清单文件
  icon.png               # 可选: 图标
  index.html             # 可选: UI 入口
  css/                   # 可选: 样式文件
  js/                    # 可选: 脚本文件
  wasm/                  # 可选: WASM 模块
  scripts/               # 可选: 钩子脚本
    ├── init.js
    ├── cleanup.js
    └── migrate.js
  data/                  # 可选: 默认数据文件
```

## 5.2 .axex 格式（加密插件）

```
容器格式: ZIP (加密)
文件扩展名: .axex
MIME 类型: application/vnd.axaihub.plugin.axex

加密方案:
  ├── 算法: AES-256-GCM
  ├── 密钥: APP 内置密钥 + 插件 ID 派生
  │         key = HKDF(APP_MASTER_KEY, plugin_id)
  ├── 认证: 加密时附加 HMAC-SHA256 签名
  └── 完整性: 签名验证失败 → 拒绝安装

包结构 (加密前):
  plugin.ns              # 明文 (不加密, 用于安装时校验)
  icon.png               # 可选: 明文 (不加密)
  wasm/
    └── main.wasm        # 加密 (AES-256-GCM)
  assets/                # 可选: 加密 (AES-256-GCM)
    ├── index.html
    ├── style.css
    └── script.js
```

### 加解密流程

```
打包 (开发者侧):
  plugin.ns (明文) + wasm (明文) + assets (明文)
    → 读取 APP_MASTER_KEY (从构建环境)
    → 对 wasm/ 和 assets/ 目录逐文件加密
    → 生成 HMAC 签名
    → 打包为 .axex ZIP

安装 (APP 侧):
  .axex ZIP
    → 读取 plugin.ns (明文, 直接解析)
    → 读取 icon.png (明文, 直接显示)
    → 验证 HMAC 签名
    → 使用 APP_MASTER_KEY + plugin_id 派生密钥
    → 解密 wasm/ 和 assets/
    → 加载到沙箱运行
```

## 5.3 格式对比

| 特性 | .axext | .axex |
|------|--------|-------|
| 代码可见性 | 明文 | 加密 |
| 打包工具 | 任意 ZIP 工具 | 专用打包 CLI |
| 安装速度 | 快（无需解密） | 较慢（需解密） |
| 适用场景 | 开源、学习、个人 | 商业、闭源 |
| 文件大小 | 较小 | 略大（加密开销） |
| 调试友好 | 是 | 否（需调试模式） |

# 6. 构建流程

## 6.1 开发构建

```
开发者工作目录:
  my-plugin/
    ├── plugin.ns
    ├── index.html
    ├── style.css
    ├── script.js
    └── icon.png

开发命令:
  $ ax build --watch          # 开发模式, 监听文件变更
  $ ax build --output plugin.axext    # 打包为 .axext
  $ ax build --encrypt --output plugin.axex  # 打包为 .axex
  $ ax build --key APP_KEY    # 指定加密密钥
  $ ax validate               # 仅校验 NS 文件
```

## 6.2 CI/CD 构建

```
代码提交 → GitHub Actions
  → 1. 安装 ax CLI 工具
  → 2. ax validate (校验 NS)
  → 3. ax build --output plugin.axext (开源构建)
  → 4. ax build --encrypt --key $SECRET --output plugin.axex (商业构建)
  → 5. 上传 artifacts
  → 6. 发布到插件市场
```

# 7. 更新机制

## 7.1 自动更新流程

```
APP 启动时 / 定时检查 (每 24 小时)
  → 遍历所有已安装且设置了 updateUrl 的插件
  → 向 updateUrl 发送 GET 请求
  → 解析响应 JSON
  → 比较 latestVersion 和当前版本
  → 有新版本 → 通知用户
  → 用户同意 → 下载新版本 .axext/.axex
  → 执行 update 钩子脚本
  → 更新完成
```

## 7.2 更新检查响应格式

```json
{
    "latestVersion": "1.2.0",
    "minAppVersion": "1.0.5",
    "downloadUrl": "https://plugins.axaihub.com/.../plugin.axext",
    "fileSize": 245760,
    "checksum": "sha256:...",
    "changelog": "### 1.2.0\n- 新增功能 X\n- 修复 Bug Y",
    "releaseDate": "2026-08-04"
}
```

## 7.3 更新安全

- 下载 URL 必须使用 HTTPS
- 下载后校验 checksum
- 更新前检查 `minAppVersion` 兼容性
- 更新失败时自动回滚到旧版本
- 保留旧版本文件直到更新确认完成

# 8. 错误处理与恢复

## 8.1 错误分类

| 错误类型 | 示例 | 处理方式 |
|---------|------|---------|
| 解析错误 | NS 格式错误 | 安装失败, 返回具体错误信息 |
| 校验错误 | 缺少必需字段 | 安装失败, 返回具体错误信息 |
| 依赖错误 | 依赖插件未安装 | 提示用户安装依赖 |
| 网络错误 | 更新检查超时 | 静默失败, 下次重试 |
| 权限错误 | 用户拒绝授权 | 返回错误码, 插件降级运行 |
| 运行时错误 | WASM 崩溃 | 断开插件连接, 记录崩溃日志 |
| 存储错误 | 配额超限 | 返回错误码, 提示用户清理 |
| 钩子错误 | 安装脚本失败 | 回滚操作, 标记安装失败 |

## 8.2 插件崩溃恢复

```
WASM 崩溃 / iframe 无响应
  → 检测到超时 (30 秒无响应)
  → 断开插件连接
  → 记录崩溃日志 (插件 ID, 时间, 调用的 API #N)
  → 通知用户: "插件 X 无响应, 已停止"
  → 用户可重新启用插件
  → 连续崩溃 3 次 → 自动禁用插件
```

## 8.3 数据一致性

- 存储操作使用事务（写入失败时回滚）
- 配置写入使用原子写入（先写临时文件，再重命名）
- 安装/卸载操作出错时回滚到上一个稳定状态

# 10. 独立窗口运行方案 (v1.1.0 新增)

> **落地状态**：独立窗口（PluginActivity）已实现基础能力——独立 Activity + 全屏 WebView、右上角控制按钮、三点点菜单、`axplugin://` 本地加载、Android 广播事件接收（`plugin_send_window_event`）。**宿主桥（postMessage 分发层）尚未注入该窗口**，其中的插件暂不能调用能力 API（storage/network/AI 等），仅适合纯展示型插件；插件列表"运行"按钮默认走同窗口模式。本节其余内容为设计稿，落地以 `docs/01-插件格式规范.md` 为准。

## 10.1 设计目标

- 每个插件在自己的 Android Activity 中运行，不共用 APP 主界面
- 可以同时使用 APP 和插件（类似微信小程序：小程序和微信本身在 Android 上不是一个 APP 窗口）
- 插件右上角有叉号按钮（关闭）和三点点按钮（菜单）
- 三点点菜单包含：包名、版本号、开发者信息、刷新、清理缓存、在浏览器中打开等快捷操作
- 支持通过 NS 注册自定义动作按钮到三点点菜单

## 10.2 架构设计

```
┌──────────────────────────────────────────────────────────────────┐
│                        Android 任务栈                             │
│                                                                  │
│  ┌──────────────────┐  ┌──────────────────┐  ┌────────────────┐ │
│  │  MainActivity     │  │  PluginActivity A │  │ PluginActivity B│ │
│  │  (APP 主界面)      │  │  (插件A独立窗口)   │  │ (插件B独立窗口)  │ │
│  │  · 对话/设置/...   │  │  · 全屏 WebView  │  │ · 全屏 WebView │ │
│  │  · 插件管理        │  │  · 右上角控制按钮 │  │ · 右上角控制按钮│ │
│  │  · 插件列表        │  │  · 三点点菜单    │  │ · 三点点菜单   │ │
│  └──────────────────┘  └──────────────────┘  └────────────────┘ │
│                                                                  │
│  通信方式: Android Broadcast (ACTION_PLUGIN_EVENT)               │
│  ┌─────────────────────┐        ┌──────────────────────────────┐ │
│  │ MainActivity        │────────▶│ PluginActivity              │ │
│  │ (发送广播)           │ 事件推送 │ (BroadcastReceiver 接收)    │ │
│  └─────────────────────┘        └──────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────┘
```

## 10.3 核心组件

### PluginActivity.kt
- 全屏 WebView 加载插件内容
- 右上角控制按钮（关闭 + 三点点菜单）
- 三点点菜单使用 PopupWindow 实现
- 通过 BroadcastReceiver 接收主 APP 发送的事件
- 支持 axplugin:// 自定义协议加载本地插件
- 支持 http/https 加载远程网页插件

### Rust 后端扩展
- `plugin_open_window`: 通过 JNI 启动 PluginActivity
- `plugin_send_window_event`: 通过 Android 广播向插件窗口发送事件
- 保留原有的 `plugin_open_remote` / `plugin_close_remote` 兼容旧模式

### 前端扩展
- `runPluginInWindow(pluginId)`: 从插件列表调用，在新窗口中打开插件（可选入口；插件列表"运行"按钮当前默认走同窗口 AxPlugin.html，即第 4 章描述的主窗口 iframe 模式）
- 回退机制：如果独立窗口启动失败，自动回退到同窗口 iframe 模式

## 10.4 通信机制

### APP → 插件 (事件推送)
1. 主 APP 调用 `plugin_send_window_event` (Rust command)
2. Rust 通过 JNI 调用 Kotlin 的 `sendBroadcast`
3. 所有 PluginActivity 实例收到广播
4. PluginActivity 通过 `evaluateJavascript` 将事件推送到插件 JS

### 插件 → APP (API 调用)
- **设计目标**：插件通过 `AX.call()` 或 `postMessage` 发送请求，经 Tauri IPC 通道到达后端，后端处理后返回结果
- **现状**：宿主桥（postMessage 分发层）当前仅注入同窗口模式的 AxPlugin.html；独立窗口（PluginActivity）**尚未注入宿主桥**，其中的插件暂不能调用能力 API（storage/network/AI 等），仅适合纯展示型插件。待注入桥后本节设计方可生效

## 10.5 安全边界

- 每个 PluginActivity 拥有独立的 WebView 实例，数据完全隔离
- 插件间无法直接通信，必须通过 APP 中转
- 关闭插件窗口时自动清理 WebView 资源（`onDestroy`）
- Intent 参数仅限必要信息（插件ID、URL等），无敏感数据泄露风险
