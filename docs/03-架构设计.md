# Anulus 插件体系架构设计

> **版本**: 1.1.0
> **对应 NS 版本**: 1
> **本文档描述当前已实现的插件体系架构**。开发契约以 [`docs/01-插件格式规范.md`](01-插件格式规范.md)、[`docs/02-打包教程.md`](02-打包教程.md)、[`docs/04-API参考.md`](04-API参考.md) 为准。

## 1. 系统架构概览

### 1.1 架构分层

```
┌──────────────────────────────────────────────────────────────────┐
│                        APP 宿主层                                │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────┐   │
│  │  插件管理器    │  │  API 桥接层   │  │  权限管理             │   │
│  │ (manage.rs)  │  │  (api.rs)    │  │ (perm_util.rs)       │   │
│  └──────┬───────┘  └──────┬───────┘  └──────────┬───────────┘   │
│         │                │                      │               │
│  ┌──────┴───────┐  ┌─────┴──────┐  ┌───────────┴───────────┐   │
│  │  NS 解析器    │  │  设备能力    │  │  授权弹窗 UI           │   │
│  │   (ns.rs)    │  │(device_cap) │  │  (插件运行页)          │   │
│  └──────┬───────┘  └────────────┘  └───────────────────────┘   │
│         │                                                       │
├─────────┼───────────────────────────────────────────────────────┤
│  ┌──────┴──────────────────────────────────────────────────┐    │
│  │                    插件运行层                            │    │
│  │  · 独立窗口模式: Tauri 第二 WebView（默认）              │    │
│  │  · 降级模式: 同窗口 AxPlugin.html 内 iframe 承载          │    │
│  │  · 隐藏静默模式: AI 调用插件时以隐藏 iframe 通信           │    │
│  │  · WASM: 与 HTML/JS 同在 WebView 内运行（无独立沙箱）      │    │
│  └─────────────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────────────────┘
```

### 1.2 核心模块

| 模块 | 文件 | 职责 |
|------|------|------|
| NS 解析器 | `plugin/ns.rs` | 解析 `.ns` 清单为内存结构，校验权限/元数据 |
| 插件管理器 | `plugin/manage.rs` | 安装、卸载、启用、禁用、列出插件 |
| API 桥接层 | `plugin/api.rs` | 命名 action 分发（`storage.read` 等）、权限检查、参数消毒 |
| 权限管理 | `plugin/perm_util.rs` | 授权记录读写、`permissions` 键解析 |
| 设备能力 | `plugin/device_cap.rs` | 相机/麦克风/定位等系统能力通道 |
| 运行桥 | `bridge_shim.js`（注入） | 插件→宿主：`AX.call(action, args)` 命名式调用分发 |
| 宿主页 | `AxPlugin.html` | 独立窗口宿主 / 降级 iframe 承载 / 隐藏静默调用载体 |

## 2. 插件运行方式

- **独立窗口模式（默认）**：插件页面作为 Tauri 第二 WebView 的顶层内容运行，与主窗口并行；通信由 Rust 注入窗口顶层的桥（`bridge_shim.js`）完成，插件侧使用参考 SDK `samples/axplugin-sdk.js` 的 `AX.call` 封装。
- **降级模式**：独立窗口启动失败时自动降级到同窗口宿主页 `AxPlugin.html`，插件本体以无 `allow-same-origin` 的 iframe 承载，桥为宿主页内的 postMessage 分发。
- **AI 调用插件（隐藏静默模式）**：宿主以隐藏 iframe 加载 `AxPlugin.html`，通过 `ai_call` postMessage 协议调用插件声明的函数（ack / heartbeat / result / error 全流程，见 docs/04 §4.2）。

## 3. 通信协议

- **插件 → 宿主**：`AX.call('action', args)`（命名 action，如 `storage.read`），经桥分发到后端，统一返回 `{result}` 或 `{error}`。
- **宿主 → 插件（AI 调用）**：`ai_call` postMessage 消息，`function` 字段承载函数标识，配套 ack / heartbeat / result / error 生命周期。
- **AI 工具寻址**：插件声明的 AI 可调用函数由 APP 统一分配全局唯一编号（P1/P2...），AI 按编号调用，开发者无需自定义编号，重名互不影响（见 docs/04 §7）。

## 4. 权限体系

- **第 1 层：插件能力授权**：`.ns` 的 `permissions` 块声明 + 运行时申请制。插件调用 `permission.request` 申请 → 宿主弹确认框 → 授权后可用；未配置即未授权。
- **第 2 层：系统权限通道**：相机/麦克风/位置/通知/联系人/日历/短信等系统权限由 APP 持有，插件经 `permission.check` / `permission.request` 借用，结果经 `permission_result` 事件异步回传。
- **APP 级专属**：电池优化豁免、无障碍服务不开放给插件，插件声明无效。
- 敏感命令（读任意文件 / 取明文密钥 / 聊天记录 / 终端 / Python 等）在 Rust 层校验「仅主窗口可用」，插件无法触达。

## 5. 打包与分发

- 打包工具 `axbuild`：`keypair`（Ed25519 签名密钥）/ `new`（模板生成）/ `pack`（打包）/ `info`（查看）。
- `.axext`：明文开源格式（zip 改后缀）；`.axex`：加密格式（AES-256-GCM + PBKDF2），源码受保护。
- 更新分发：开发者分发新版 `.axext` / `.axex` 文件，用户导入新版文件即覆盖旧版。

## 6. 安全机制

- 权限声明 + 运行时授权弹窗；域名白名单 + 请求限频；CSP 限制。
- 敏感命令仅主窗口可用（Rust 层校验）。
- AI 调用插件需用户授权（授权记录校验 + 授权框确认）。

## 7. 事件

事件经 `event.subscribe` / `event.unsubscribe` 订阅（`lifecycle` 无需订阅，自动派发）：`lifecycle` / `permission_result` / `camera_result` / `mic_result` / `speech_result`。

## 8. WASM

插件可在页面内直接用 `fetch` + `WebAssembly.instantiate` 加载 `.wasm`（与浏览器一致），在 WebView 内与页面 JS 同上下文运行，无独立沙箱。
